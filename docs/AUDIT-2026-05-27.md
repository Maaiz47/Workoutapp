## 1. QA system flaws

**[verified] CRITICAL — `note` is required for every status, including `passing`.**
`app/api/qa/comment/route.ts` rejects any submission with an empty `note`
(`typeof note !== "string" || note.trim().length === 0`). The dashboard's own
`noteRequired = draft.status !== "passing"` heuristic implies a bare "passing"
verdict should be allowed — but the API 400s it, and the UI surfaces a generic
error. Net effect: a tester can't tap "works now" and move on; they're forced to
type something. **Fix:** only require `note` for `failing` / `regression-retest`
/ `untested`; allow empty for `passing`. (Confirm this is the desired UX first —
if notes are deliberately mandatory, the fix is instead to make the UI stop
implying otherwise.)

**[verified] MEDIUM — empty-string `itemId` passes validation.**
Same file: `if (!itemId || typeof itemId !== "string")` lets `""` through if it
ever arrives as a non-empty falsy-adjacent value via odd clients; add an
explicit `itemId.trim().length === 0` guard to match the `tester` check right
below it (which already does this).

**[unverified] HIGH — retest parent-status flip matches the parent by the last
8 chars of the comment id.** Reported in `app/api/qa/comment/route.ts`
(`c.id.slice(-8)`). Two concerns: (a) collision risk if two comments in one item
share an 8-char tail, (b) concurrent retests racing on the same parent with no
lock. **Fix:** match on the full id carried in the retest marker.

**[unverified] HIGH — `qa-processed.json` / `qa-comment` JSON parse failures
swallow the error** (`catch { return {} }` in three routes). A corrupt manifest
silently makes every comment look unprocessed. **Fix:** `console.error` in the
catch so it's visible in Vercel logs.

**[unverified] MEDIUM — `qa-scan.ts` only audits the 10 most recent PATCHLOG
sections** (`.slice(0, 10)`). A feature shipped >10 sections ago without a
`(qa: …)` tag won't be flagged. **Fix:** make the window a `--limit=` arg.

**[unverified] MEDIUM — `vercel-should-skip.sh` doesn't list `qa-processed.json`
or `PATCHLOG.md` as deploy-skippable.** Pushing a processing pass triggers a full
redeploy. That's actually *desired* for `qa-processed.json` (it's read at request
time and a redeploy makes the state live immediately) but `PATCHLOG.md`-only
pushes burn a deploy for nothing. Worth confirming against the documented intent
in CLAUDE.md before changing.

**[unverified] LOW — `isAuthorized()` + `readProcessedManifest()` are copy-pasted
across 3 routes.** Extract to `lib/qaAuth.ts` / `lib/qaProcessed.ts` so the admin
gate has one definition.

## 2. UI flaws (mobile-first / iPhone)

**[unverified] HIGH — sub-44px touch targets.** Several controls are below
Apple's 44×44 minimum: hydration +/- (~30×34), soreness rating buttons (~22),
photo-delete (~22), superset-select circles (~22). These cause mis-taps on a
phone. Bump hit areas (visual size can stay small with padded tap zones).

**[unverified] HIGH — centered modals lack `maxHeight` / `overflowY`.** Milestone,
PB, and form-preview modals use `inset:0` + `maxWidth` but no height clamp; with
the iOS keyboard up or in landscape they can overflow with no scroll. Add
`maxHeight: 90dvh; overflowY: auto` to modal bodies. (Note: the profile-preview
modal I shipped already needs this audit too — it's centered with fixed padding.)

**[verified] MEDIUM — z-index ladder is ad hoc and partially colliding.** Current
values: effort prompt 9995, rest timer 9999, QA tab/overlay ~9500, profile
preview 9050, tier-promo/PB/milestone toasts 9000–9200. A 9000-level celebration
can render *behind* the 9050 profile modal. Recommend a documented ladder, e.g.
toasts 8900–8999, modals 9000–9099, system overlays 9100–9499, QA 9500, blocking
UI (rest timer) 9900+. Centralize as named constants.

**[unverified] MEDIUM — silent fetch failures show stale/blank UI.** Global
leaderboard, avatar picker, and group leaderboard all `.catch(() => {})` with no
error state — an API hiccup leaves an empty list with no retry affordance. Add a
minimal error+retry row.

**[unverified] LOW — list keys use array index in a few spots** (text-link
splitter, SVG chart points, some PB lists). Fine until the list reorders; prefer
stable ids.

**[unverified] LOW — magic color strings everywhere** (`rgba(255,255,255,0.3/.4/.5)`
repeated 200+ times). A small set of CSS custom properties (`--text-dim`,
`--text-mute`) would stop drift. Low priority, high churn — do opportunistically.

**[verified] RISKY DUPLICATION — muscle-group → balance-bucket mapping is
copy-pasted** between `lib/leaderboardStats.ts` (server) and the

recommendation:** extract a shared `lib/muscleBuckets.ts` + a shared RPE-bonus
helper and have both sides import it. This is the single highest-value refactor
in the codebase — it's load-bearing scoring logic maintained in two places.

## 4. Achievements — shipped + further ideas

**Shipped this pass (15):** `year-two`, `streak-365`, `prs-250`,
`hipthrust-100kg/180kg`, `legpress-200kg/300kg`, `plate-trio`, `two-plate-club`,
`hiit-100`, `cardio-time-300/1200/3000` (5/20/50 hrs — activates the dormant
`totalCardioMinutes` field), `volume-5m/10m`. All non-premium (no avatar art
dependency) and all read fields already populated in `MilestoneState`, so they
fire correctly with no new plumbing.

**Further ideas (need new plumbing or art):**
1. **Progress bars on locked achievements.** Today the wall is binary
   locked/unlocked. Showing "7/10 sessions" or "92/100 kg" toward the next rung
   is the highest-impact engagement upgrade and the data is already in
   `MilestoneState`.
2. **Bodyweight-relative strength badges** (1×/1.5×/2× BW bench/squat/DL).
   Fairer across body sizes than absolute kg; needs bodyweight in
   `MilestoneState` (currently absent — add `bodyweightKg`).
3. **Premium variants of the new elite tiers** (e.g. `volume-10m`,
   `streak-365`) once avatar art exists — wire via `unlocksMilestoneId` like the
   existing 5 `mb-*` avatars. Tracked in `image-prompts-v2.md`.
4. **"Comeback" achievement** — return and log after a 30+ day gap. Rewards
   re-engagement instead of only punishing broken streaks.

## 5. Feature upgrades / new options (prioritized)

**High value**
- **Achievement progress bars** (see §4.1).
- **Streak resilience**: a "rest day doesn't break the streak if within plan"
  rule, or 1–2 "freeze" tokens. The current any-missed-day-breaks model is
  punishing for a rest-day-aware app and discourages the deloads the app itself
  recommends.
- **Profile preview → full read-only stats.** The new profile modal is a natural
  home for a "View full profile" expansion (tier sub-rank breakdown, top lifts,
  achievement count) — all already computable server-side.
- **Streak-at-risk push notification.** Infra exists (`/api/push`). A single
  evening nudge when today has no session and the streak is live.

**Medium value**
- **Shareable weekly recap card** (image export of the existing recap).
- **Per-exercise PR history graph** in the exercise detail view.
- **React to friends' achievements** in the system feed (reactions infra exists).
- **CSV / JSON data export** in Settings (trust + retention).

**Lower / longer-horizon**
- **Apple Health / wearable import** for cardio + bodyweight (kills manual entry,
  feeds the cardio-time achievements automatically).
- **Tier-change transparency**: when the headline tier drops, a one-line "why"
  (which sub-rank fell) — especially relevant after the new-user ramp + decay.
